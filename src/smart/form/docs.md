# sf-form

Форма из описаний полей: подпись, «*», «?», подсказка и ошибка вокруг каждого
поля, группы, раскладка, сводка ошибок и кнопки. Сами поля рисует общий модуль
SIMAI Framework `field-renderers` (`SF.fieldRenderers`, `renderEditField` и
`renderViewField`) — тот же, что у карточки записи `sf-view-properties`, у
таблицы и у фильтров. Решение владельца C182 (2026-11-14).

```html
<sf-form label="Кнопка в письме">
  <script type="application/json" data-sf-settings>
    {"groups": [{"key": "content", "label": "Содержимое"}, {"key": "look", "label": "Оформление"}],
     "fields": [
       {"key": "text", "label": "Текст", "propertyType": "string", "required": true, "group": "content", "hint": "Не длиннее 30 знаков"},
       {"key": "url", "label": "Ссылка", "propertyType": "string", "required": true, "group": "content"},
       {"key": "tone", "label": "Тон", "propertyType": "choice", "width": "medium", "group": "look",
        "options": [{"value": "accent", "label": "Акцент"}, {"value": "quiet", "label": "Тихая"}]},
       {"key": "radius", "label": "Скругление, px", "propertyType": "number", "decimals": 0, "width": "short", "min": 0, "max": 24,
        "help": "Только для залитой кнопки", "group": "look"}],
     "value": {"text": "Подробнее", "url": "https://simai.io", "tone": "accent", "radius": 8}}
  </script>
</sf-form>
```

Где нужна: правка записи, страница настроек (`labels="start"`,
`footer="sticky"`), параметры блока в редакторе (`apply="instant"`), заявка и
регистрация на сайте. Не нужна: фильтры над таблицей (это `renderFilterField`),
строки меню настроек (`sf-settings`).

## Описание поля

То же описание, что передаёт `sf-view-properties`: тип и параметры из реестра
свойств (`SF.fieldRenderers.registry`: `propertyType`, `template` и
`templateParams` (C302; `variant` — старое имя `template` до 2027-01-01),
`required`, `readonly`, `placeholder`, `options`, `min`, `max`, `step`, `unit`,
`decimals`, у денег `currency`, `currencies`, `currencyDisplay` …) и:

| Ключ | Что значит |
| --- | --- |
| `key` | имя значения в `value` |
| `label` | подпись над полем; ею же назван элемент управления |
| `hint` | подсказка под полем; ошибка встаёт на её место; экранный диктор читает её вместе с полем (`aria-describedby`) |
| `help` | пояснение за «?» (`sf-help-mark`) после подписи; у «да / нет» флажком — после подписи рядом с флажком, того же размера (1.14.2) |
| `width` | `short` — поле не шире 20 знаков (160 px при тексте 16), `medium` — 28 знаков (224 px), `full` — во всю строку; это шаги ширины поля `--sf-field--width-short` и `-medium`, те же, что у настройки `width` самих полей. Прежние `s` и `m` (8rem и 16rem) до 2027-01-01 рисуются как `short` и `medium` и один раз отмечаются в `SF.deprecations` |
| `group` | ключ группы из `groups` |
| `origin` | откуда значение (1.15.0, C422): `{value, level, locked, reason, own, above, inherited}` — ниже, «Откуда значение» |
| `autocomplete` | подсказка браузера для текстовых полей; у почты по умолчанию `email` (1.15.0) |

Короткий выбор — `choice` или `choices` не больше чем из пяти вариантов — форма
рисует готовой группой `sf-input-choice` с `appearance="list"` (C165): выбор
одного — радиокнопки, выбор нескольких — флажки, до трёх коротких вариантов в
строку, остальное столбиком. Подпись, «*», «?» и подсказка — формы, как у
любого поля; ошибка — под последней строкой группы. Длинный список —
выпадающий; шаблон не по умолчанию (`template: "buttons"` или `"checklist"`) и
старое `variant: "select"` оставляют полю свой элемент.

Почта — тип `email` (1.15.0, `field-renderers` 1.30.0): одно поле адреса с
клавиатурой почты и подсказкой браузера (`autocomplete="email"` или своё
`autocomplete` поля), проверка «Нужен адрес почты: name@example.ru» — один
ящик, домен из двух частей и больше, не длиннее 254 знаков; в просмотре и в
строке таблицы — ссылка `mailto:`.

Поле типа, которого `field-renderers` не рисует, не показывается — кроме
типов набора компонентов (`items`, `complex`, `ru.requisites`), когда их рисует
хозяин полей (`fieldHost.renderField`, ниже).
`readonly: true` — значение текстом, а не выключенное поле.

## Условия полей

`when` в описании поля (1.4.0) говорит, когда поле показано (`visible`),
обязательно (`required`) и доступно для изменения (`enabled`). Каждое — условие
над значениями других полей, какими они стоят на экране сейчас, до сохранения:
поле появляется в тот момент, когда выбрано значение, которого оно ждёт.

| Условие | Когда верно |
| --- | --- |
| `{"field": "k", "op": "eq", "value": v}` | значение поля `k` равно `v` (у поля с несколькими значениями — любое из них) |
| `{"field": "k", "op": "ne", "value": v}` | не равно |
| `{"field": "k", "op": "in", "value": [v1, v2]}` | одно из перечисленных |
| `{"field": "k", "op": "not_in", "value": [v1, v2]}` | ни одно из перечисленных |
| `{"field": "k", "op": "empty"}` | поле пустое: нет значения, пустая строка, пустой список |
| `{"field": "k", "op": "not_empty"}` | поле заполнено |
| `{"field": "k", "op": "gt", "value": 1000}` | число (точно, без округления) или дата ISO в поле больше значения; список и пустое поле не сравниваются; `"gte"` — больше или равно, `"lt"` — меньше, `"lte"` — меньше или равно |
| `{"all": [ … ]}` | верны все условия |
| `{"any": [ … ]}` | верно хотя бы одно |
| `{"not": { … }}` | условие неверно |

Значения сравниваются как текст: `5` и `"5"` — одно значение, у `{value,
label}` берётся `value`. Скрытое поле сохраняет значение и не проверяется; его
ошибка уходит. Недоступное поле (`enabled` неверно) показано значением
текстом, как `readonly`. Условие, которое нельзя прочитать (неизвестный `op`,
пустой `all`), оставляет поле таким, как оно описано.

```json
{"fields": [
  {"key": "delivery", "label": "Доставка", "propertyType": "choice",
   "options": [{"value": "courier", "label": "Курьером"}, {"value": "pickup", "label": "Самовывоз"}]},
  {"key": "address", "label": "Адрес", "propertyType": "string",
   "when": {"visible": {"field": "delivery", "op": "eq", "value": "courier"},
            "required": {"field": "delivery", "op": "eq", "value": "courier"}}}
]}
```

Те же функции доступны странице: `SF.fieldRenderers.conditions.field(field,
values)` отвечает `{visible, required, enabled}`,
`SF.fieldRenderers.conditions.evaluate(condition, values)` — одно условие.

## Настройки

- `fields` — поля по порядку (см. выше).
- `groups` — группы `{key, label}`. От двух групп каждая — `fieldset` с
  заголовком, между группами 24 и линия.
- `apply` — `submit` (по умолчанию): кнопки «Сохранить» и «Отмена» под полями;
  `instant`: каждое изменение применяется сразу, кнопок нет. Вид «да / нет»
  задаёт шаблон поля (C303 (4)): переключатель по умолчанию, `checkbox` —
  флажок с подписью рядом, `buttons` — кнопки «Да» | «Нет». Обязательность
  (`required`) читают кнопки — у них есть «не задано»: обязательное
  поле с кнопками получает «*» и не отправляется без ответа, необязательное
  сбрасывается повторным нажатием выбранной кнопки (1.12.3). Обязательный
  флажок своего шаблона `checkbox` — согласие («Я согласен с условиями»):
  без галочки форма не отправляется, под флажком ошибка «Заполните поле…»,
  он в списке `sf-form-invalid` (1.14.0). Переключатель (и переключатель,
  нарисованный флажком в форме с кнопкой) отвечает своим значением;
  `answer`: анкета, на которую отвечают один раз (сообщение в чате, запись в
  ленте; C291 (3)) — «Отправить» и «Отмена», после ответа значения текстом с
  отметкой «Отправлено» и без «Изменить». `mode` в этом режиме не читается.
- `size` — `1` (по умолчанию) или `1/2`: поля и кнопки на ступень меньше, для
  формы в сообщении. Подпись, подсказка и ошибка — на ступени текста 1/2 при
  обоих.
- `state` — только при `apply="answer"`: где ответ, слова поверхности
  подтверждения (`sf-confirm`). `open` — поля и кнопки; `pending` — ответ в
  пути: поля заперты, нажатая кнопка ждёт, строка «Отправляем…» («Отменяем…»);
  `accepted` — отправленные значения текстом и «Отправлено»; `declined` —
  ничего (C35: отказ ничего не говорит); `expired` — только «Время ответа
  истекло». Исход ставит хозяин.
- `labels` — `top` (по умолчанию): подпись над полем; `start`: подпись
  слева, поле справа (C401, 1.14.0). Подписи группы стоят одной колонкой
  шириной по самой длинной, не шире 40 % строки, все поля начинаются на
  одной линии. Переключается так же, как `layout="auto"` у
  `sf-list-description` (C180 (3)): подпись слева, когда форма шире 20rem
  (и в узкой боковой панели), над полем — в более узкой и на телефоне
  (уже md). Поэтому группа записи, открытая на правку на месте, держит
  подписи там же, где они были при чтении.
- `footer` — `static` (по умолчанию): кнопки под последним полем; `sticky`:
  кнопки в полосе, прилипающей к низу прокручиваемого места (страница
  настроек, C166 (3)).
- `label` — имя формы для экранного диктора (ориентир «форма»).
- `origin` — слова уровней для полей с `origin` (1.15.0): `own`, `above`,
  `inherited`, `locked` (раздел «Откуда значение»).
- `guard` — вопрос «Уйти без сохранения?» при уходе со страницы (1.15.0).
- `readonly`, `readonly-reason` — форма только для чтения и причина (1.15.0).
- `fieldHost` — только свойство (1.7.0): та часть хозяина полей, которую держит
  запись (карточка `sf-view-properties`), чтобы правка любой группы шла в
  `sf-form`:
  - `getFieldOptionsPage`, `getFieldOptionSearch`, `setFieldOptionSearch`,
    `loadFieldOptions` — страницы и поиск выбора записи, связи и сотрудника
    (`record`, `relation`, `user`, шаблон `reference_picker`);
  - `getFieldUploads`, `startFieldUpload`, `retryFieldUpload` — передача файла
    (шаблон `upload`): форма рисует поле загрузки, и оно само говорит свою
    ошибку под собой;
  - `getFieldText`, `formatFieldValue` — слова и формат хозяина;
  - `renderField(field, value, host, {editing, size})` — тип, который рисует
    набор компонентов (`items`, `complex`, `ru.requisites`).

  Каждый вызывается с аргументами `field-renderers` и последним аргументом —
  хозяином формы для этого поля: его `setFieldValue` пишет в значение формы
  (например, сохранённый файл, когда загрузка закончилась). Значения, проверки
  (обязательный выбор, файл, строки) и то, что получит сервер, остаются
  формы, в формах реестра типов: выбранная запись `{value, label}`, файл —
  в форме хозяина, строки — список. Без `fieldHost` выбор берёт свои
  варианты из `options` поля, а файловое поле держит выбранные файлы в
  значении (`{name, size, mime, file}`, сам `File` — хозяину отправить вместе
  со значениями); выбор, который некому листать, показывает значение текстом.

Рабочие имена, которые ещё подтверждает владелец: `top`, `static`, `fields`,
`groups`, `label`, `mode`, `dirty`, `set-errors`, событие `cancel`.

## Откуда значение (origin)

Страница настроек с уровнями (решение C422): у значения сайта может быть общее
значение уровня выше («Все сайты»). Поле с `origin` показывает под собой тихую
строку только там, где это важно:

- своё значение — «Своё для simai.ru · у всех сайтов: Москва, UTC+3» и кнопка
  «Вернуть общее»; уровень считает сама форма: значение не равно
  `origin.value` — своё, равно — общее;
- закрыто выше (`origin.locked: true`) — поле только для чтения, под ним
  причина (`origin.reason`);
- общее значение — без строки; слова `inherited` («Как у всех сайтов») —
  только если хозяин их задал.

Слова уровня задают один раз настройкой формы `origin`: `{own: "Своё для
simai.ru", above: "у всех сайтов", inherited: "Как у всех сайтов", locked:
"Закрыто на уровне «Все сайты»"}`; слова у поля важнее. Без слов — «Своё
значение · общее: …», «Закрыто на уровне выше».

«Вернуть общее» шлёт отменяемое `sf-form-reset-field {key, value}`, затем
ставит в поле общее значение как правку человека: форма изменена до
«Сохранить» (в `apply="instant"` — применяется сразу), фокус — в поле. В
`sf-form-submit` приходит `inherited` — ключи, значение которых снова равно
общему: хозяин может хранить их как «общее», а не как своё.

## Сохранение, занятость и «Сохранено в …»

- Не отменённое `sf-form-submit` — значения сохранены, под кнопками
  «Сохранено в 14:35» (время читателя) до следующей правки.
- Хозяин, который сохраняет сам, отменяет `sf-form-submit`, ставит
  `busy = true` и отвечает: `saved()` — сохранено (форма чистая, «Сохранено в
  …»), `setErrors(...)` — ошибки, новый `value` или `busy = false`. Пока
  `busy`, «Сохранить» показывает загрузку своего цвета, «Отмена» ждёт, поля
  только для чтения — как окно при сохранении (C159 (9)); повторное нажатие и
  Enter ничего не делают.
- `saved-at` — когда сохранили (ISO), можно задать и из кода.

## Уход с несохранёнными изменениями (guard)

`guard` (1.15.0, C166 (6), C422): пока есть несохранённые изменения, закрытие
вкладки спрашивает браузер, а нажатие ссылки, которая уводит со страницы
(другая страница или адрес-маршрут, которому нет места на странице), форма
задерживает — меню и маршрутизатор страницы его не слышат. Уходит отменяемое
`sf-form-leave {href}`; если хозяин его не отменил, форма спрашивает в окне
«Уйти без сохранения?» с ответами C159 (6): «Не сохранять» (красная, первая:
поля возвращаются, ссылка нажимается снова) и «Продолжить правку» (тихая, с
фокусом: страница и отметка меню остаются). Ссылка внутри формы, в новую
вкладку, на скачивание или с клавишей-модификатором проходит. Свой переход
хозяина спрашивает `confirmLeave()`: `applied` — можно уходить, `refused
{reason: stayed}` — остались.

## Только чтение (readonly)

`readonly` (1.15.0, C348, C422) — у человека нет права менять: значения
текстом, как в `mode="view"`, без «Изменить» и без «Сохранить»; на месте
кнопок — причина `readonly-reason` («Менять настройки сайта может
администратор сайта»; по умолчанию «Только чтение»). Пункт полосы сообщений
над страницей ставит хозяин (`sf-alert-bar`).

## Значения

- `value` — значения по ключам. Заданное из кода — сохранённое состояние:
  форма показывает его, забывает ошибки и не считается изменённой.
  Целое число (`number` с `decimals: 0`, прежний `integer`) — всегда число
  или `null`, когда поле пустое: в `value`, в событиях `input`, `submit`,
  `answer` и `cancel` будет `30`, введено ли оно с клавиатуры или задано из
  кода строкой `"30"` (1.14.2). Число со знаками после запятой остаётся
  десятичной строкой (`"12.30"`), как его передаёт порт свойств.
- `mode` — `edit` (по умолчанию) или `view`: значения текстом и «Изменить».
  Пустое значение в `view` — тихое слово «Не указан», то же, что у
  `sf-list-description` (1.9.0). Выбор в `view` — тоновая метка (C308 (3)).
- `valid` — все поля сейчас верны (только чтение, ничего не показывает).
- `dirty` — есть несохранённые изменения (только чтение).
- `busy` — хозяин сохраняет (1.15.0, выше).
- `saved-at` — когда сохранили, «Сохранено в HH:MM» (1.15.0).

## Раскладка

Одна колонка. От 44rem собственной ширины поля без `width` встают по два,
через 32; поля `s`, `m` и `full` — в своей строке. Уже — одна колонка.
Между полями 16, между группами и перед кнопками 24, подпись над полем через 4
(C52, C105).

## Ошибки

Сроки — как у всех полей (C153 (3)): после «Сохранить» — у всех неверных
полей; потом — у поля, которое изменили и покинули; ошибка уходит, как только
значение стало верным. Слова — формы («Заполните поле «Текст»»), самого
поля (о формате, о границах) или хозяина (`set-errors`). Поля семейства
`sf-input` и `sf-dropdown` показывают ошибку в своей строке сообщения, у
остальных строку рисует форма.

Ошибка поля, которое покинули нажатием мыши или пальца на форме, появляется,
когда нажатие закончилось: строка ошибки не сдвигает «Сохранить» из-под
указателя, и нажатие сохраняет форму (или показывает все ошибки) с первого
раза.

От двух ошибок после «Сохранить» над формой встаёт сводка: «Исправьте 2
поля» и ссылка на каждое поле. Фокус переходит на сводку (`role="alert"`),
ссылка переводит фокус в своё поле. Одна ошибка — фокус сразу в поле.

## Кнопки

Под полями, главная первой в начале: «Сохранить», затем «Отмена», через 8
(C159 (4)). «Сохранить» всегда доступна — форма сама скажет, что не так.
После первого изменения под кнопками — «Есть несохранённые изменения».
Enter в однострочном поле сохраняет форму. Нажатие «Сохранить» и Enter форма
обрабатывает сама, без отправки формы браузером, поэтому `sf-form-submit` и
`sf-form-invalid` приходят и в изолированном фрейме без `allow-forms`.

## Ответ (apply="answer")

Анкета в сообщении: `apply="answer" size="1/2"`. «Отправить» проверяет поля,
как «Сохранить»; если всё верно, форма переходит в `pending` и шлёт
`sf-form-answer {accepted: true, value}`, «Отмена» — `{accepted: false}`.
Хозяин ставит исход в обработчике или позже: `state="accepted"` (просмотр с
«Отправлено»), `state="declined"`, или снова `open` — тогда `setErrors`
покажет, что исправить. Отменённое событие — ответ не принят, форма снова
открыта. Строка состояния всегда на странице (вежливая живая область) и
получает фокус, когда кнопки уходят. Деньги и проценты рисуются полями SIMAI
Framework (C291 (2)).

## События

| Событие | Когда | `detail` |
| --- | --- | --- |
| `sf-form-input` | поле изменили (каждый ввод) | `{key, value}` |
| `sf-form-change` | `apply="instant"`: изменение применено — одно на изменение: текст, когда поле его зафиксировало (ушли из поля, Enter), выбор и флажок сразу | `{key, value}` |
| `sf-form-submit` | «Сохранить», все поля верны; отменяемое | `{value, inherited}` |
| `sf-form-reset-field` | «Вернуть общее»; отменяемое | `{key, value}` |
| `sf-form-leave` | `guard`: ссылка уводит со страницы при несохранённых изменениях; отменяемое | `{href}` |
| `sf-form-invalid` | проверка нашла ошибки | `{fields}` |
| `sf-form-cancel` | «Отмена» | `{value}` |
| `sf-form-answer` | `apply="answer"`: «Отправить» или «Отмена»; отменяемое | `{accepted, value?}` |

`value` в `sf-form-input` и `sf-form-change` — значение поля любого типа:
текст, число, да / нет, список или объект.

Не отменённое `sf-form-submit` делает значения сохранёнными; форма, открытая
из просмотра, возвращается в просмотр. Отменённое — форма остаётся как есть:
хозяин ответит `set-errors` или новым `value`.

## Действия

- `checkValidity()` — проверить и показать ошибки; `applied` или
  `refused {reason: invalid}`.
- `reset()` — вернуть сохранённые значения, без событий.
- `setErrors({errors: {url: "Адрес уже занят"}})` — ошибки хозяина у полей.
- `saved({at})` — хозяин сохранил сам: значения сохранены, `busy` снят,
  «Сохранено в HH:MM» (1.15.0).
- `confirmLeave()` — спросить «Уйти без сохранения?» перед своим переходом
  (1.15.0).
- `refreshFields()` — ответы хозяина полей изменились (страница вариантов,
  ход загрузки): поля рисуются заново (1.7.0). Когда вызов хозяина отвечает
  обещанием, форма перерисовывается сама, как только оно выполнено.
