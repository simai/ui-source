# sf-wizard

Мастер — процесс из нескольких шагов, который человек проходит один раз, а
продукт между шагами делает работу: первая настройка сервера, установщик,
импорт CSV, установка пакета, создание сайта. Рамка мастера (`sf-wizard`)
рисует ход по шагам, заголовок и пояснение шага, само тело шага и одну строку
кнопок; каждый шаг — дочерний `sf-wizard-step`, его дети — тело шага: форма из
полей Framework, картинка, состояние, план изменений.

```html
<sf-wizard heading="Новый сайт">
  <sf-wizard-step name="name" label="Название" type="form"
    description="Так сайт будет называться в панели и в заголовке страниц.">
    <form>
      <sf-input name="title" label="Название сайта" required></sf-input>
    </form>
  </sf-wizard-step>
  <sf-wizard-step name="template" label="Шаблон" type="info">
    <p>Шаблон «Магазин»: каталог, корзина и оплата уже настроены.</p>
  </sf-wizard-step>
  <sf-wizard-step name="done" label="Готово" type="result">
    <p>Сайт создан.</p>
  </sf-wizard-step>
</sf-wizard>
```

Человек вводит данные и запускает действие внутри мастера: в другой раздел его
не отправляют. Если раздел действительно нужен, он открывается окном поверх
мастера или ссылкой с возвратом. Мастер ничего не хранит за хозяина: состояния
шагов — атрибуты шагов, ответы — его значение `value`, каждое движение и
нажатие — событие.

## Шаги

| Атрибут `sf-wizard-step` | |
|---|---|
| `name` | Ключ шага: его называет `current`, его несут события, под ним ответы шага в `value`. Пусто — `step-1`, `step-2`… |
| `label` | Короткое имя в ходе по шагам. |
| `heading` | Заголовок над телом шага; пусто — `label`. |
| `description` | Зачем этот шаг, одно-два предложения под заголовком. |
| `type` | `info`, `form`, `action`, `review`, `result` — см. ниже. |
| `optional` | Шаг можно пропустить: появляется «Пропустить». |
| `href` | Место `pages`: адрес шага. |
| `action-text` | Подпись главной кнопки на этом шаге вместо слова типа. |
| `message` | Чем кончилось действие шага, одно предложение. |
| `state` | `done`, `skipped`, `running`, `error`; пусто — не начат. |

Заголовок, пояснение, индикатор выполнения, итог и кнопки рисует мастер по
атрибутам: в тело шага их не пишут.

### Типы шагов и главная кнопка

| `type` | Что делает | Главная кнопка |
|---|---|---|
| `info` | показывает текст или картинку | «Далее» |
| `form` | поля Framework, проверка, ошибки у полей; «Далее» сохраняет шаг | «Далее» |
| `action` | запускает долгое действие | «Запустить» → пока идёт, кнопка ждёт → «Далее» после успеха, «Повторить» после ошибки |
| `review` | сводка введённого с «Изменить» у каждого пункта (план изменений) | «Применить» |
| `result` | что получилось и куда дальше; кнопки «Назад» нет | «Готово» |

На последнем шаге любого типа главная кнопка — «Готово». `action-text`
заменяет слово типа («Выпустить сертификат», «Импортировать»); «Повторить» и
«Далее» после действия остаются своими.

### Состояния

Не начат, текущий, сделан (`done`), пропущен (`skipped`), выполняется
(`running`), ошибка (`error`). Текущий — тот, что называет `current`, какое бы
состояние у него ни было. В местах `inline` и `modal` мастер сам ставит шагу
`done` или `skipped`, когда человек идёт дальше; хозяин пишет `state` и
`message` для действия:

```js
wizard.addEventListener('sf-wizard-submit', async (event) => {
  if (event.detail.action !== 'run' && event.detail.action !== 'retry') return;
  event.preventDefault();               // действие выполняет хозяин
  const step = wizard.querySelector('sf-wizard-step[name="run"]');
  step.setAttribute('state', 'running');
  try {
    await importContacts(event.detail.value);
    step.setAttribute('message', 'Добавлено 124 контакта.');
    step.setAttribute('state', 'done');  // итог и «Далее»
  } catch (error) {
    step.setAttribute('message', error.message);
    step.setAttribute('state', 'error'); // итог и «Повторить»
  }
});
```

Пока шаг выполняется, в нём индикатор (`sf-spinner`) и строка `message` или
`running-text`, тело помечено `aria-busy`, главная кнопка показывает свой
спиннер, и любое нажатие ждёт: второй раз действие не отправить. Итог —
`sf-alert` статуса успеха или ошибки.

### План изменений

Тело шага-сводки — список `ul.sf-wizard-plan`: строка на изменение, что и
на что слева, «Изменить» (`sf-button` с `data-wizard-step`) справа, тонкая
линия между строками.

```html
<ul class="sf-wizard-plan">
  <li><span><b>Адрес панели</b> — panel.example.ru</span>
    <sf-button appearance="link" size="1/2" text="Изменить" href="/setup/address" data-wizard-step="address"></sf-button></li>
</ul>
```

## Ход по шагам

`progress="auto"` (по умолчанию): до 7 шагов — ряд сверху (`sf-steps`), больше
7 — «Шаг 4 из 12», полоса (`sf-progress-bar`) и «Все шаги», который открывает
список всех шагов. `progress="row"` и `progress="count"` выбирают одно из двух.
`progress="column"` — колонка шагов слева внутри рамки мастера, когда ширина
мастера не меньше 40rem (для мастеров от 8 шагов на широком экране). Уже 40rem
мастер всегда показывает компактную шапку: текущий шаг и полосу. Колонки во
всю высоту страницы вне мастера нет.

`navigation` — какие шаги открывает нажатие в ходе по шагам:

- `linear` (по умолчанию): любой шаг до первого не сделанного и не пропущенного;
- `free`: любой;
- `visited`: уже пройденный (сделан, пропущен, с ошибкой) и текущий.

«Далее» и «Назад» всегда идут по порядку. Любой элемент шага с
`data-wizard-step="<name>"` открывает тот шаг по тем же правилам — так
устроено «Изменить» в сводке.

## Кнопки

Внизу одна строка в постоянном порядке: «Назад» в начале (на первом шаге и
на шаге-итоге её нет), «Пропустить» (необязательный шаг) и одна главная
кнопка в конце. Главная кнопка всегда одна. Все кнопки — `sf-button`; при
грубом указателе (палец) кнопки шапки и низа, шаги ряда и строки списка не
ниже 44px.

## Проверка полей

«Далее» проверяет поля шага штатной проверкой браузера: `required`, `type`,
`pattern`, `min`, `max`, собственная проверка поля формы. Каждое неверное поле
Framework получает `invalid` и сообщение (текст браузера, если страница не
дала своего `error-message`), первое получает фокус, приходит
`sf-wizard-invalid`, шаг остаётся. Когда человек правит поле, мастер снимает
то, что поставил сам. Ошибки, которые напечатал сервер, остаются.

Нажатие Enter в поле шага отправляет шаг так же, как главная кнопка.

## Где показывается (`place`)

### `inline`

Мастер стоит в странице. «Далее» проверяет поля, отправляет `sf-wizard-submit`
и, если его не отменили, отмечает шаг сделанным и показывает следующий.

### `modal`

Окно (`sf-modal`), которое открывает элемент страницы, названный в `for`, или
действие `open()`:

```html
<sf-button id="csv-open" text="Импорт CSV"></sf-button>
<sf-wizard place="modal" for="csv-open" heading="Импорт контактов" remember="csv-import" later>
  …шаги…
</sf-wizard>
```

Закрытие окна (крестик, Escape, подложка) при введённых и не отправленных
данных сначала спрашивает «Закрыть мастер? Введённое на этом шаге не
сохранится.» (`sf-confirm`). После последнего шага окно закрывается и
приходит `sf-wizard-completed`.

### `pages` — страница на шаг

Каждый шаг — своя страница сервера; в браузере ничего не хранится. Сервер
печатает мастер со всеми шагами (`name`, `label`, `href`, `state`), а тело —
только у текущего; `current` называет текущий:

```html
<sf-wizard place="pages" heading="Настройка сервера" current="protection" later-href="/" focus-title>
  <sf-wizard-step name="address" label="Адрес панели" href="/setup/address" state="done"></sf-wizard-step>
  <sf-wizard-step name="notify" label="Уведомления" href="/setup/notify" optional state="skipped"></sf-wizard-step>
  <sf-wizard-step name="protection" label="Защита" type="action" href="/setup/protection"
    action-text="Выпустить сертификат" state="error"
    message="Let’s Encrypt не ответил: домен пока не указывает на этот сервер.">
    <form method="post" action="/setup/protection">…</form>
  </sf-wizard-step>
  <sf-wizard-step name="backups" label="Копии" href="/setup/backups"></sf-wizard-step>
</sf-wizard>
```

- Главная кнопка — кнопка отправки формы шага: `sf-button native-type="submit"
  form="<id формы>" name="wizard-action" value="next|run|retry|apply|done"`
  (sf-button 1.5.0). Браузер отправляет форму шага со словом нажатой кнопки,
  мастер не добавляет скрытых полей. Имя — `action-name`. Форме без `id`
  мастер даёт свой.
- «Пропустить» отправляет форму со словом `skip` без проверки полей.
- «Назад» и ход по шагам — ссылки на `href` шагов.
- Шаг без формы идёт по `href` следующего шага, последний — по `done-href`.
- Шаг-действие сразу показывает «выполняется», пока сервер работает.
- Сервер отвечает той же страницей мастера: тот же шаг с ошибками у полей
  (`invalid`, `error-message`) или с итогом (`state`, `message`), либо
  следующий шаг. `focus-title` на такой странице даёт фокус заголовку шага.

#### Что печатает сервер в первом кадре

Чтобы страница не мигала, сервер печатает мастер так, как его рисует код:
рамку, ход по шагам и кнопки — статической разметкой (`data-sf-static`), а
шаги — внутри рамки, в контейнере `data-sf-live`, **один раз** и такими, как
есть, с первым кадром их полей. Мастер забирает шаги оттуда живыми в том же
кадре, в котором рисует себя: формы шага на странице всегда одна, её поля и
ошибки сервера сохраняются. Готовую разметку для каждого состояния дают
снимки `static/default/server-*.html` (обновляются
`scripts/snapshot-first-paint.mjs`); сервер подставляет в них свои значения.

## «Продолжить позже» и закрытие

`later` (или `later-href`) рисует «Продолжить позже». Нажатие отправляет
`sf-wizard-close` с `reason: later`, текущим шагом, состояниями всех шагов и
ответами; затем окно закрывается или браузер идёт на `later-href`. С
`remember="<ключ>"` мастер в местах `inline` и `modal` запоминает в этом
браузере текущий шаг, состояния и ответы (`SF.Preferences`, ключ
`sf-wizard/<ключ>`; копия браузера — `localStorage` `sf-pref:sf-wizard/<ключ>`,
хозяин, который хранит настройки человека, получает их тоже) и в следующий
раз открывается там же; после
завершения запись удаляется. Место `pages` ничего не хранит: место знает
сервер.

Если на текущем шаге есть введённое и не отправленное, «Продолжить позже» и
закрытие окна сначала спрашивают; `sf-wizard-close` приходит только после
согласия.

## Одно значение

`value` — все ответы всех шагов по имени шага и имени поля:

```json
{"address": {"host": "panel.example.ru"}, "backups": {"keep": "7", "daily": "1"}}
```

Мастер собирает его из именованных полей шагов (порядок FormData; имя,
данное дважды, — список). `value` только читается; его несут `change`,
`submit`, `close` и `completed`.

В месте `modal` шаги на время открытого окна стоят в окне (`sf-modal`
рисует его в конце страницы): находите шаг по `id`, а не через
`wizard.querySelector`.

## События

| Событие | `detail` | |
|---|---|---|
| `sf-wizard-change` | `{previous, current, value}` | Человек перешёл на другой шаг. Не приходит для `goToStep` и записи `current`. |
| `sf-wizard-submit` | `{step, action, values, value}` | Главная кнопка или «Пропустить», поля верны. Отменяемый запрос: отменённый — работу делает хозяин; не отменённый — `pages` отправляет форму, `inline`/`modal` отмечают шаг и идут дальше. `action`: `next`, `run`, `retry`, `apply`, `done`, `skip`. |
| `sf-wizard-invalid` | `{step, fields}` | Поля шага неверны; ничего не отправлено. |
| `sf-wizard-navigate` | `{id, href}` | Место `pages`: переход по адресу шага. Отменяемый: отменённый — страница переходит сама. |
| `sf-wizard-open` | `{}` | Место `modal`: окно открывается. Отменяемый. |
| `sf-wizard-close` | `{reason, current, steps, value}` | Человек уходит: `later`, `close`, `escape`, `outside`, `api`. Отменяемый. |
| `sf-wizard-completed` | `{steps, value}` | Места `inline` и `modal`: последний шаг отправлен. |

| `heading` | | Что делает мастер, строка над ходом по шагам. |

## Действия

- `open()`, `close()` — окно места `modal`.
- `goToStep({name})` — показать шаг; `{outcome: 'refused', reason: 'missing' | 'current'}`.
- `next()` — нажать главную кнопку: проверка, `submit`, переход;
  `refused` с `busy`, `invalid` или `prevented`.

## Доступность

Мастер — область (`role="region"`), названная `heading`. Текущий шаг в ряду
и в списке отмечен `aria-current="step"`, состояние шага входит в его имя.
После перехода фокус получает заголовок шага (`role="heading"`,
`tabindex="-1"`), а скрытая строка состояния говорит «Шаг 3 из 6:
Уведомления». Пока шаг выполняется, тело помечено `aria-busy`. Все кнопки —
нативные кнопки и ссылки `sf-button`. Тёмная тема — из темы страницы.
