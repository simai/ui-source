# Smart Image Field

`<sf-image-field>` — поле формы для одного изображения: логотипа, обложки,
картинки в блоке. Показывает миниатюру, имя файла и размер, кнопки
«Заменить…» и «Убрать». Файл можно перетащить прямо на поле — он заменит
изображение. Пустое поле предлагает выбрать изображение или перетащить его.

```html
<sf-image-field label="Логотип" name="logo" hint="PNG или SVG, до 1 МБ"
  value='{"value":"42","label":"logo.png","mime":"image/png","size":2048,"href":"/upload/logo.png"}'></sf-image-field>

<sf-image-field label="Обложка" name="cover" required></sf-image-field>
```

## Значение

`value` — изображение в той же форме, в какой Фреймворк везде описывает файл:

```js
{value: '42', label: 'logo.png', mime: 'image/png', size: 2048, href: '/upload/logo.png'}
```

- `value` — идентификатор файла у хоста;
- `label` — имя файла, оно же `alt` миниатюры;
- `mime` — тип файла;
- `size` — размер в байтах (число) или готовый текст;
- `href` — адрес, по которому изображение показывается.

В атрибут можно передать эту форму как JSON или просто адрес картинки.
Свойство `value` принимает объект или `null` (пусто). Значение, заданное из
кода, событий не вызывает — как у обычного поля.

## Загрузка — у хоста

Компонент сам ничего не загружает, как и `sf-file-upload`. Когда человек
выбирает или перетаскивает файл, миниатюра сразу показывает его (через
временный адрес `blob:`), а хост получает сам `File` в событиях. Хост
загружает файл и записывает в `value` сохранённое значение с постоянным
`href`.

```js
field.addEventListener('sf-image-field:select', async (event) => {
  const stored = await upload(event.detail.file);
  field.value = stored; // {value, label, mime, size, href}
});
```

Выбранный файл уходит и с обычной отправкой формы под именем `name`: внутри
лежит платформенное поле файла.

## Атрибуты

- `label` — подпись над полем, она же имя группы. Без неё группа называется
  «Изображение».
- `hint` — подсказка под полем; слот `hint` — разметкой.
- `error`, `invalid`, `error-message` — ошибка: рамка и текст красятся в цвет
  ошибки, текст ошибки встаёт вместо подсказки; слот `error` — разметкой.
  Метод `setError('…')` делает то же из кода, `setError()` снимает ошибку.
- `required` — без изображения форма не отправится.
- `disabled` — поле видно, кнопки недоступны, файл не принимается.
- `readonly` — изображение видно, кнопок нет.
- `accept` — какие файлы предлагает диалог и принимает перетаскивание. По
  умолчанию `image/*`.
- `size` — `1/2`, `1` (по умолчанию), `2`, как у всех полей формы.
- `meta` — своя строка под именем. По умолчанию — размеры картинки, когда она
  загрузится, и размер файла: «450×300 · 2 КБ».
- `empty-text` — свой текст пустого поля.

## События

- `input`, затем `change` — один раз на каждое действие человека (выбор,
  перетаскивание, «Убрать»). `detail`: `{value, file, source, name}`, где
  `source` — `input`, `drop` или `remove`.
- `sf-image-field:select` — выбран файл: `{file, source, value, name}`.
- `sf-image-field:remove` — изображение убрано: `{value, name}` с прежним
  значением.
- `sf-image-field:reject` — перетащенный файл не подходит под `accept`:
  `{files, accept, source}`.

Методы: `setValue(value)`, `clear()`, `setError(message)`, `choose()` (открыть
диалог), `removeImage()`, `takeFile(file, source)`.

## Клавиатура и чтение с экрана

Поле — группа с именем из подписи; подсказка или ошибка её описывают.
«Заменить…», «Убрать» и «Выбрать…» — настоящие кнопки с понятными именами:
«Заменить изображение «logo.png»». Сама область перетаскивания фокус не
берёт, поэтому Tab проходит по кнопкам и уходит дальше. После «Убрать» фокус
встаёт на «Выбрать…». Выбор, удаление и неподходящий файл вежливо
объявляются.

Размеры берутся из одной шкалы: миниатюра — высота поля на ступень крупнее
(у поля размера `1` это 48 px на компьютере и 44 px на телефоне), кнопки — на
ступень мельче поля. В узкой колонке (уже 24rem) кнопки уходят под имя файла.
