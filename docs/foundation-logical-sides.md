# Логические стороны Smart-компонентов

Статус: реализованный контракт кандидата; публичная поставка проходит общий release gate.

`start` означает начало, `end` — конец в направлении письма конкретного контейнера. В RTL начало находится справа. Направление определяется CSS/DOM, а не перестановкой данных или ручным зеркалированием всех иконок.

| Компонент | Канонический параметр | Совместимое имя SF5 |
| --- | --- | --- |
| sf-button, sf-badge | iconStart / icon-start | iconLeft / icon-left |
| sf-button, sf-badge | iconEnd / icon-end | iconRight / icon-right |
| sf-input | iconStart / icon-start | leftIcon / left-icon |
| sf-input | textEnd / text-end | rightText / right-text |
| sf-datepicker | iconStart / icon-start | leftIcon / left-icon |
| Элемент данных sf-tabs | iconStart / icon-start в компактной строке | iconLeft / icon-left |
| Элемент данных sf-tabs | iconEnd / icon-end в компактной строке | iconRight / icon-right |

Для кнопок и бейджей добавлены слоты `icon-start` и `icon-end`; старые `icon-left` и `icon-right` сохранены. Для поля — `start` и `end` вместо `left` и `right`. Канонический слот с содержимым имеет приоритет и не создаёт второй экземпляр элемента.

При одновременном задании параметров канонический имеет приоритет независимо от порядка. Явно пустой канонический параметр скрывает соответствующий контент; его удаление возвращает legacy-значение. Для кнопок/бейджей отсутствие обоих имён сохраняет прежнее поведение общего `icon` и `icon-position`. Старые имена в этих реализациях уже имели логическую семантику: переименование не меняет порядок DOM.

Legacy-поля контекста шаблона получают разрешённое значение, чтобы существующие внешние шаблоны могли продолжать работу. CSS-классы и токены с историческими именами не переименовываются вслепую. Физические координаты, ось X, направление анимации и значения вне данного списка требуют самостоятельной проверки; они не становятся логическими автоматически.

В кандидате проверены приоритеты параметров/слотов и отображение кнопок/бейджей при смене LTR/RTL и вложенном противоположном dir. Поле и выбор даты проверены с конфликтующими старыми/новыми параметрами, их изменением и удалением. Для вкладок проверены компактная строка, объектные данные, сохранение через setState и последующий рендер, в том числе явное пустое значение новой иконки. Эти браузерные сценарии проходят в Chromium, Firefox и WebKit.

Внутренние кнопки действий таблицы и административного меню используют iconStart, а поиск меню — icon-start. Это обновление потребителей, не заявление о готовности нового контракта данных узлов admin-menu: там исторические leftIcon/rightIcon требуют отдельного разбора (rightIcon присутствует в модели, но не используется текущим шаблоном). Реестр и Studio публикуют канонические имена рядом с совместимыми псевдонимами. Docara и точные published locks обновляются только общей согласованной поставкой. Эта таблица описывает конкретно реализованное покрытие, не обещает поддержку новых имён всеми компонентами.
